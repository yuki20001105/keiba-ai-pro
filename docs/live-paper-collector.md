## 操作

リポジトリのルートで実行します。表示されたPIDではなく、専用の停止コマンドを使用してください。

```powershell
# 状況（未来の予定も表示）
.\python-api\.venv\Scripts\python.exe scripts/inspect_forward_collector.py

# 停止要求。現在の記録を壊さず、新しい処理を止める
.\python-api\.venv\Scripts\python.exe scripts/run_forward_collector.py stop --root reports/generated/forward-runtime/h04-live-20260920-v2

# 明示停止後の再開
.\scripts\start-forward-collector.ps1 -ResumeStopped
```

二重起動はSQLiteの単一所有者leaseで拒否します。異常終了した捕捉は「状態不明」とし、自動で同一レースをやり直しません。手動停止の解除には `-ResumeStopped` が必要です。ソース・モデル・校正器・ルールのハッシュが変わると捕捉を拒否します。研究中にそれらを更新する場合は、新しい事前計画と保管先が必要です。

台帳が保存の確定点です。JSON出力失敗時も、確定済みの捕捉は消したり再取得したりしません。停止・失敗・見送り・未確認・未精算を区別し、成功したレースだけを分母にしない設計です。

ただしこれは開催前夜の技術検証です。「本物の発走5分前に取得して、決着後に精算する」運用実証はまだです。実際の締切を迎える次の開催から蓄積します。技術検証のデータを前向き実績に混ぜていません。

## 精算と評価

決着後の完全な着順表と単勝払戻を照合し、100円単勝の固定シミュレーションを精算します。同着はそれぞれの払戻を使用します。未公表・不足・不明は未精算であり、負けの0円にも近似払戻にも置き換えません。netkeiba掲載の結果・払戻が出典で、JRAの電子署名付き証跡ではありません。

予測精度と買い目成績は別集計です。予測側は順位相関、正規化順位RMSE、NLL、Brier、固定10区間の校正表、1位推奨の勝率を表示します。H04は順位モデルなので、このRMSEは速度のRMSEではありません。買わなかったレースも予測評価に含め、全頭の着順が揃わないレースは順位相関・RMSEからレース単位で除外理由を残します。評価定義は開始前の2026-09-19 23:57に `analysis-definition.json` へ別途固定済み。再校正・ルール調整・モデル再学習は行いません。

精算未確定の購入が1件でもある場合、全体回収率は未確定です。確認済みの部分だけの数字は別表示し、履歴上の市場オッズを使った過去評価とも分離します。最低母数は確定した1,000レース・30開催日。条件を満たすために都合よく期間を延長しません。

**事前計画の制約:** 現在の開催カレンダーでは、この90日間は29開催日・69会場開催です。1会場最大12レースでも上限828レースで、障害除外・収集失敗分はさらに減ります。従来計画の「最低30開催日・1,000レース」は現予定のままでは達成できません。集めた結果を十分な確認実績と見なさず、母数不足を明示します。期間や必要母数の見直しは、別の事前計画・承認事項であり、今回自動変更していません。
