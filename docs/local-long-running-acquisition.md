# ローカルの長時間データ取得

## 目的

管理機能の15分再認証と、取得ジョブの寿命を分離する。ログイン画面への移動やブラウザを閉じる操作で、承認して開始した期間の取得を途中で打ち切らない。

## 認証と実行の境界

- ローカル管理画面は、明示的なローカル設定・ループバック接続・有効なログイン・現在の管理者ロールが揃った場合だけ、15分の追加確認なしで使用できる。
- 管理者ロールやアクセストークン自体を無期限にする変更ではない。開始・状態確認・停止のAPIは都度認証・認可し、所有者を確認する。
- ログアウト・管理者ロール取消後の新規操作は拒否する。一時的な認証サービス障害は「未確認」として扱い、操作を止めてもサーバーのジョブIDは失わない。
- 外部公開環境の管理機能の短期確認は維持する。ローカルの例外を公開環境へ適用しない。

## 全期間ジョブ

ローカル起動スクリプトは `LOCAL_ADMIN_SESSION_ENABLED=true` を明示設定する。Next.jsを別の方法で起動する場合は、`APP_ENV=development` と `ML_API_URL` / `SCRAPE_API_URL` のループバック設定も必要。設定なし・公開環境では短期確認のままである。

1. 画面は送信前に親ジョブID・操作ID・対象期間を利用者ごとに保存する。
2. 全期間を一度だけサーバーへ送信し、既存の所有者ロック・実行台帳・leaseに載せる。
3. Pythonが月単位で順次処理し、各月の完了結果を記録する。完了した月は再実行しない。
4. 通信応答を失った場合も新しいジョブを勝手に作らず、保存したIDで状態を照合する。
5. 再ログイン・画面再表示では同じジョブに再接続する。画面を閉じることと、明示的な停止操作を区別する。

受付記録が確認できない場合の「同じ依頼を再送」は、認証済みの状態照会で元のIDが未受付であることを確認し、利用者が明示確認した場合だけ使用する。ID・期間・取得方式は変更しない。再送が拒否されても元のIDを保持する。履歴から復元した依頼は元の操作IDを持たないため、再送せず状態照会だけを行う。

停止は親ジョブに対して要求し、処理中の月を安全な保存境界で止める。停止後は次月を開始しない。保存済みデータを削除しない。

## 運用上の注意

- ブラウザは閉じられるが、PythonサーバーとPCの稼働は必要。PCの電源断・スリープ中に取得は進まない。
- ネットワークへの実アクセスは既存の共通速度制御を使用する。キャッシュ再利用・品質判定・HTTP制限時の減速を維持する。
- 以前の「約120分」は一覧URLだけの計算で、全期間の完了予測ではない。今回の変更によって通信込みの取得全体が5倍になったと判断するものではない。
- 旧版のジョブIDなしロックは、「前回の取得を探す」から自分の終了済み履歴を選び、対象期間・開始時刻を確認して照合する。その後「状態を再確認」で終端状態を確認する。サーバー記録と一致しない場合は解除しない。旧月間バッチの1ヶ月完了を、全期間完了とは扱わない。

## 検証方針

実データの取得を開始せず、一時DBと通信モックで月継続・完了月の再利用・停止・再接続・認証失効・所有者分離を検証する。起動中アプリへの反映は、実行中の取得・学習ジョブがないことを確認してから行う。
