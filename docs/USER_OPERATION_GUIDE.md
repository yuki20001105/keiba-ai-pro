## 1. この手順書について

この文書は、Production Webアプリ「競馬AI Pro」を安全に操作するための利用者向け手順書です。一般利用者が使用する予測・分析画面と、Premium/Admin専用画面を区別して説明します。

アプリURL: <https://keiba-ai-pro.vercel.app>

### 現在のリリース状態

- WebアプリはLimited Productionとして公開されています。
- モデルの運用状態は`observation`です。
- 自動購入・自動ベットは無効です。
- 表示される購入推奨やvirtual betは検証用で、実際の馬券購入ではありません。
- 90日、1,000 settled samples、100 qualifying betsを含むModel Business Validationは継続中です。
- モデル学習・モデル有効化・Production設定変更は一般利用者の操作対象外です。

| --- | --- | --- | --- |
| ログイン・ホーム | 利用可 | 利用可 | 利用可 |
| 予測実行画面 | 閲覧・操作可 | 利用可 | レース一覧取得は接続状況に依存 |
| 予測スコア詳細 | 閲覧可 | 利用可 | 対象レースがDBにある場合に表示 |

| 本番前チェック | 利用不可 | ホーム導線なし | 保守用URL・操作境界の本人確認が必要 |

## 3. 利用モードとワンクリック起動

### 一般ユーザー: Production Web版

通常の利用者は<https://keiba-ai-pro.vercel.app>を開くだけです。PCへNode.js、Python、DBを導入する必要はありません。

Production Web版で「スクレイプAPIの状態を確認できません」と表示される問題は、スクレイプ系APIだけがVercel内部の`localhost:8000`を参照していたことが原因です。修正版では、専用URLがない場合に通常のRender FastAPIへ接続します。修正版のProductionデプロイが完了するまでは、次のローカル版を使用できます。

### 管理・開発ユーザー: ローカル完全版

このリポジトリ、承認済み環境ファイル、Python venv、Node依存、SQLite DB、モデルが揃っているPCでは、BATファイルから一括起動できます。

1. エクスプローラーでリポジトリ直下を開きます。
2. `start-keiba-ai-pro.bat`をダブルクリックします。
3. FastAPIとNext.jsのhealth確認が終わるまで待ちます。
4. ブラウザで<http://127.0.0.1:3000/login>が自動的に開きます。
5. 登録済みアカウントでログインします。

起動スクリプトは次を自動実行します。

- FastAPIを`127.0.0.1:8000`で起動
- Next.jsを`127.0.0.1:3000`で起動
- FastAPIとWeb側プロキシのhealthを確認
- ログを`logs/local-app/`へ保存
- Observationモード、スケジューラ停止、実投票資格情報なしで安全に起動

補助BATは次のとおりです。

| ファイル | 用途 |
| --- | --- |
| `start-keiba-ai-pro.bat` | アプリを一括起動してログイン画面を開く |
| `check-keiba-ai-pro.bat` | FastAPIとNext.jsの稼働状態を確認する |
| `stop-keiba-ai-pro.bat` | 起動BATが開始したプロセスだけを停止する |

停止BATは、他のNode.jsやPythonプロセスを一括終了しません。起動時に記録したPIDとプロセスツリーだけを停止します。

起動BATを誤って2回実行しても、既存プロセスを二重起動したり停止用PIDを上書きしたりしません。すでに正常起動している場合は、そのままログイン画面を開きます。

### ローカル起動に必要なもの

- `node_modules`とNode.js 24.x
- `python-api/.venv`（唯一のローカルPython環境）
- `.env.local`と必要な認証設定
- `keiba/data/keiba_ultimate.db`
- `python-api/models`内のモデル

これらは秘密情報や大容量DBを含むため、BATから自動ダウンロードしません。不足時は安全のため起動を中止し、画面に不足項目を表示します。

## 4. ログイン

1. <https://keiba-ai-pro.vercel.app/login>を開きます。
2. 登録済みのメールアドレスを入力します。
3. 更新済みのパスワードを入力します。
4. 「ログイン」を押します。
5. 「AI競馬予測」ホーム画面が表示されることを確認します。

![ログイン画面](assets/user-operation-guide/00-login.png)

### ログイン時の注意

- パスワードやAPIキーをチャット、Issue、画面キャプチャへ貼らないでください。
- ログインできない場合は、メールアドレスの前後に空白がないか確認します。
- 認証エラーが続く場合は、エラー文と発生時刻だけを管理者へ連絡します。パスワード自体は送らないでください。

## 5. ホーム画面

ログイン後のホーム画面は一つだけで、画面モードの切り替えはありません。Adminロールでは次の5機能を表示し、一般ユーザーでは管理操作を非表示にして「予測実行」と「成績確認」だけを表示します。Admin専用機能を初めて開く際は、その操作境界で現在のパスワードを確認します。

### 基本メニュー

1. データ取得: 期間を指定してレース情報を取得します。
2. モデル作成: 学習条件を設定し、予測モデルの作成状態を確認します。
3. 予測実行: 日付とモデルを指定して対象レースを表示します。
4. 成績確認: virtual betや予測結果の成績を確認します。
5. ユーザー管理: 登録ユーザーを閲覧します。

一般利用者は「予測実行」から開始します。馬ごとのスコア詳細は予測結果内で確認し、特徴量と結果照合が必要な場合だけ詳細画面を開きます。

## 6. 予測を実行する

1. ホーム画面の「予測実行」を押します。
2. 「日付」に開催日を指定します。
3. 「使用モデル」は通常「最新モデルを自動選択」のままにします。
4. 賭け設定は検証用の表示です。Observation運用中は実購入されません。
5. 「レース一覧を取得」を押します。
6. レース一覧が表示されたら対象レースを選択します。
7. 予測順位、予測勝率、オッズ、期待値、推奨表示を確認します。

![予測実行画面](assets/user-operation-guide/04-predict-batch.png)

### 適格なレースの条件

検証用の正規観測として扱う場合は、次をすべて満たす必要があります。

- 実在する将来レースであること
- 結果確定前であること
- オッズ状態が`middle`であること
- 距離、出走馬、人気、オッズが揃っていること
- オッズ取得から30分以内であること

`yoso`、結果確定後のデータ、欠損したオッズ、合成データは正規証跡に使用しません。

### 「スクレイプエラー: fetch failed」と表示された場合

2026-08-23のProduction確認では、レース一覧取得時にこのエラーが表示されました。これは入力ミスではなく、スクレイプ系APIがVercel内部の`localhost:8000`を参照していたことが原因です。修正版のProductionデプロイ前はローカル完全版を使用し、デプロイ後も継続する場合は管理者へ連絡します。

![レース一覧取得時の接続エラー](assets/user-operation-guide/04b-predict-race-list.png)

1. 連続クリックや強制再取得は行いません。
2. 発生日時、指定日、表示されたエラー文を記録します。
3. 管理者へ連絡します。
4. Productionの定期Observation収集は別経路なので、Web画面のエラーだけで停止判断はしません。

## 7. 予測スコア詳細を確認する

1. 「予測実行」で対象レースを予測します。
2. 予測結果のレースカードを開きます。
3. 馬ごとの順位、生スコア、勝率、複勝圏、アンサンブル、期待値、オッズ、人気を確認します。
4. 特徴量または実際の結果との照合が必要な場合は「特徴量・結果照合を詳しく見る」を押します。
5. 詳細画面では選択した日付とレースが自動的に引き継がれます。

「特徴量・結果照合を詳しく見る」はPremium/Admin専用です。一般利用者の予測結果には、主要なスコア項目だけが表示されます。

![予測スコア詳細画面](assets/user-operation-guide/06-race-analysis-loaded.png)

「レースが見つかりません」と表示された場合は、その日付のレースがWeb画面の参照DBに存在しません。日付を確認し、管理者へデータ状況を問い合わせてください。Production画面からデータ取得を強行しないでください。

## 8. 成績と予測履歴を確認する

### 成績確認

ホーム画面の「成績確認」から、購入履歴、損益、回収率を確認します。Observation運用中の購入情報はvirtual betであり、実購入履歴ではありません。

画面が読み込み中のまま変化しない場合は、30秒待ってから1回だけ再読み込みします。改善しない場合は、発生時刻とURLを管理者へ連絡します。

### 予測履歴

成績画面上部の「予測履歴」から開きます。「予測履歴」はPremium/Admin専用です。一般利用者にはAPIを呼び出さず、権限不足画面を表示します。

![予測履歴の権限制御](assets/user-operation-guide/07-prediction-history-loaded.png)

権限不足は障害ではありません。閲覧が必要な場合は、管理者が利用目的を確認して権限を付与します。

## 9. 管理者向け画面

### 管理機能の表示

Adminロールでログインすると、ホームに5機能が自動表示されます。画面上の「管理者モード」切り替えはありません。`/data-collection`、`/train`、`/user-management`を開く時だけ現在のパスワードを確認し、確認後15分間は再入力なしで管理機能を利用できます。一般ユーザーがURLを直接開いた場合も内容をマウントせず`/home`へ戻ります。

### データ取得

「データ取得」はローカル収集APIまたは承認済み管理経路を前提とします。Production画面で「スクレイプAPIの状態を確認できません」「ローカルAPI確認不可」と表示される場合、取得ボタンは使用しません。

![データ取得画面](assets/user-operation-guide/02-data-collection.png)

通常画面には、「期間」「事前確認」「取得開始」、進捗・状態不明時の安全確認、「最新」1件、「保存済み」3指標だけを表示します。修復・再取得計画、限定ライブ検証、監査キュー、プロファイリングなどの保守機能は削除していませんが、誤操作を避けるため通常画面からは非表示です。

通常画面から開始する取得は常に`force_rescrape=false`です。既存データを対象にする修復取得は、通常画面から実行しません。

#### ローカル完全版での安全な取得手順

1. `start-keiba-ai-pro.bat`をダブルクリックします。
2. Adminロールでログインし、ホームの「01 データ取得」を開きます。
3. 画面上部が「バックエンドAPI 稼働中」になることを確認します。
4. まず1か月だけ指定し、「事前確認」を実行します。
5. 「新規」「既存」「時間」を確認します。
6. 必要な期間だけ「取得開始」を実行します。通常取得は`force_rescrape=false`で固定されています。
7. 完了結果と「保存済み」の「レース」「出走馬」「最終」を確認します。再読込後は直近結果が「最新」に表示されます。
8. 利用終了時は`stop-keiba-ai-pro.bat`を実行します。

ローカル起動時は`SUPABASE_DATA_ENABLED=false`、`NETKEIBA_RACE_WRITE_ENABLED=false`で起動するため、取得結果はローカル研究DBへ保存し、Production DBや自動購入を変更しません。広い期間を一度に取得すると外部サイトへのアクセス数と所要時間が増えるため、必ず「事前確認」後に月単位で進めます。

赤い「実行状態不明」が表示された場合は、新しい取得を開始せず「状態を再確認」を使用します。この表示と実行ロックは、重複ジョブを防ぐ安全機能なので通常画面の簡素化後も残ります。

別の取得が進行中の場合、画面には期間・受付または開始時刻・IDを表示し、完了まで事前確認と取得開始を無効にします。状態は自動再確認されます。60秒を超える事前確認はユーザー別のブラウザ保存領域にIDを保持し、画面再読込後も同じjobを確認します。

開始済みのjobを止める場合は、実行中カードの「停止」（開始待ちは「取消」）を押します。確認後は「停止中」と表示され、安全な区切りで保存を終えてから「停止しました」に変わります。画面は停止完了まで状態を自動再確認し、事前確認と取得開始を無効にします。

停止前に保存済みのデータは削除されません。未処理期間が必要な場合は、停止完了を確認してから再度取得してください。停止要求の応答を確認できない場合もjobが継続中の可能性を前提にロックを維持するため、連続クリックや別タブからの再実行は行いません。

`stop-keiba-ai-pro.bat`やブラウザ終了はプロセス／監視の停止であり、個別jobのキャンセルではありません。ジョブDBの直接編集やPythonプロセスだけの強制終了は行わず、画面の停止操作を使用してください。

2026-08-23の動作確認では、BAT起動後にFastAPI/Web health、認証、実レース一覧36件、1日分の非書き込み事前確認まで確認しています。

### モデル作成

Productionではモデル学習は常に無効です。ローカル完全版を`start-keiba-ai-pro.bat`で起動した場合だけ、Adminロールの利用者が現在のパスワードで管理機能を本人確認し、画面とローカルAPIの利用可否確認が成功すると「モデル作成」が有効になります。一般利用者、本人確認前のAdmin、またはローカル学習が無効な環境では実行できません。

この実行はローカル専用の`local-admin-train`であり、本番用の二者承認済み学習ではありません。ただし、安全機構は共通で、SQLiteのオンラインスナップショットとハッシュ、CAS lease・fence・heartbeat、実行時のactive model／code照合、成果物ハッシュを使用します。完成したモデルは候補のままで、自動的に有効化されません。

![モデル学習画面](assets/user-operation-guide/03-train.png)

モデル候補の作成、評価、承認、Activationは、Release Contractとtrusted evidenceを用いた別の管理手順で行います。

### ユーザー管理

ホームの「05 ユーザー管理」から、登録ユーザーのメールアドレス、名前、現在のロール、プラン、登録日を確認できます。管理者とユーザーを切り替える操作は現在表示しません。

## 10. 安全な利用ルール

- 自動ベットは常に無効であることを前提にします。
- Observation表示を利益保証やモデル承認済みの意味として扱いません。
- 実際の馬券購入判断は本アプリの検証範囲外です。
- APIキー、service-role key、パスワード、環境変数値を画面共有しません。
- Productionで強制再取得、モデル学習、モデル有効化、DB変更を行いません。
- 同じボタンを短時間に繰り返し押しません。
- 結果確定後のレースを前向き観測として登録しません。

## 11. トラブルシューティング

| 表示・症状 | 意味 | 対応 |
| --- | --- | --- |
| APIが確認中のまま | health応答待ち | 30秒待ち、1回だけ再読込 |
| APIオフライン | health確認失敗 | 時刻とURLを管理者へ連絡 |
| スクレイプエラー: fetch failed | Web画面と収集APIの接続失敗 | 再取得を連打せず管理者へ連絡 |
| レースが見つかりません | 指定日の参照データなし | 日付確認、データ状況を問い合わせ |
| モデルがありません | Web画面がモデルを参照できない | 学習を開始せず管理者へ連絡 |
| Premium専用 | 現在の権限では利用不可 | 必要性を管理者へ申請 |
| 読み込み表示が終わらない | APIまたはDB応答待ち | 30秒後に1回再読込、継続時は連絡 |

### 管理者へ連絡するときに記録する項目

- 発生日時（JST）
- 操作したURL
- 押したボタンまたは入力した日付
- 画面に表示されたエラー文
- 再読み込みを1回実施したか

パスワード、APIキー、Cookie、Authorization headerは記録・送信しません。

## 12. 利用終了

1. 右上の「ログアウト」を押します。
2. ログイン画面へ戻ったことを確認します。
3. ローカル完全版では、データ取得が終端状態であることを確認してから`stop-keiba-ai-pro.bat`を実行します。
4. 共用PCの場合はブラウザタブを閉じます。
