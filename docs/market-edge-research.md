# 市場オッズに対する追加情報の研究

## 2つの系統

- Track A: `h04-live-20260920-v2`。モデル、99特徴量、校正器、購入条件、protocol、評価定義を変更しない前向きペーパー検証。
- Track B: `reports/generated/model-experiments/market-edge-v1/`。過去データによる別研究。候補を保存するだけで、使用中モデルや実購入には接続しない。

研究の結果が良くても、Track Aへ自動反映しません。採用には別の事前計画・protocol・前向き検証が必要です。

## 今回の比較

1. 市場のみ: 単勝オッズの逆数をレース内で正規化。
2. H04のみ: 各前年までで学習したH04の保存済み予測を確率化。
3. 市場＋H04: 市場のlogitを基準に、ロジスティック回帰または小規模LightGBMで補正。
4. 対照実験: H04を使わない同じロジスティック補正。改善が単なる市場確率の再校正なのかを区別。

現在の稼働H04は後年まで学習しているため、そのまま2021年の予測に使いません。また、稼働校正器は2021〜2022年を使っているので、この期間の公平な比較には使いません。稼働校正器の結果は、混入のある参考値としてのみ区別して保存します。

## 期間の分離

| 期間 | 用途 |
|---|---|
| 2021年1〜6月 | 研究用H04の確率校正 |
| 2021年7〜9月 | 補正モデルの学習 |
| 2021年10〜12月 | 開発評価・保守的確率の係数・購入範囲の境界 |
| 2021年7〜12月 | 事前定義した最終学習 |
| 2022年 | 検証・候補の比較 |
| 2023年以降 | 停止条件に該当せず、候補等を完全固定できた場合のみ確認 |

過去のH04特徴量探索でも2021〜2022年は使っています。今回の期間分離はメタモデルの未来情報混入を避けますが、「全く未使用の検証期間」には戻せません。

## 回収率の読み方

- 過去オッズの観測時刻が未確認なので、回収率は実際に購入可能だったことを証明しない参考値です。
- 対象は単勝100円・1レース最大1点。実購入はありません。
- 通常期待値と保守的期待値を区別します。
- 保守的確率は、開発期間の最大期待値馬をオッズ帯別に集計したWilson下限から作る割引値です。個々の馬の勝率の保証下限ではありません。
- 購入対象の予測勝率と実勝率を優先して確認します。
- 日単位のbootstrap区間、最大払戻除外、上位3払戻除外、利益集中度も確認します。
- 閾値一覧や購入範囲の一覧で偶然100%を超えた条件を、採用済みの成功として扱いません。
- 停止条件に該当したら、Optunaや後年の評価へ進まず、今回の結果を保存します。

## 実行と保護

`scripts/run_market_edge.py` は今回の固定キャンペーン用です。`train` は既存ジョブ台帳がある場合、再実行を拒否します。`evaluate` は計画・データ・研究コードのハッシュが違えば拒否します。既存成果物を削除して再試行してはいけません。再研究する場合は新しい計画と保存先を用意してください。

実行ジョブは低優先度、CPU1枠＋GPU1枠を上限とし、メモリ・CPU・GPU・ディスク・collector・捕捉予定から投入を判断します。GPUは隔離環境のみ使用し、限定性能比較以外は有利な場合だけ採用します。

捕捉時間の前後は研究を停止／一時停止します。研究の停止対象は起動元が所有するプロセスだけで、既存Pythonサーバーやcollectorは停止しません。

## 主な記録

- `experiment_plan.json` / `research_freeze.json`: 事前条件とハッシュ
- `provenance.json`: 学習期間・元モデル・データ品質の来歴
- `compute_plan.json` / `job_ledger.sqlite`: ジョブ仕様・状態・資源監視
- `model_comparison.json` / `selection_calibration.json`: 予測評価・選択後の校正
- `coverage_roi.csv` / `threshold_analysis.csv`: 固定した条件の診断
- `bootstrap_results.json`: 回収率の不確実性と大穴依存
- `policy.json`: 未採用候補・停止判定
- `summary.md` / `audit.md` / `artifact_manifest.json`: 結論・制約・成果物照合

Track Aの再起動運用は `docs/forward-restart-resilience.md` を参照してください。ログオン前の収集復旧や、PCが停止している間の発走前捕捉は保証しません。
