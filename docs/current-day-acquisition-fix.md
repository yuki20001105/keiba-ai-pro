# 当日取得と失敗表示の修正（2026-09-19）

## 問題

9月19日の取得ジョブは受理されたが、カレンダー・日別一覧がHTTP 400を返し、代替のモバイル月間結果には9月13日までのデータしか含まれていなかった。月間索引で対象日が欠落している場合も空の結果を早期に返していた。ジョブの処理終了と取得成功は別だが、予測画面は終了後のDB再読込で失敗理由を消していた。

## 修正

- 直近日は日付指定の出馬表一覧を月間結果キャッシュより先に確認する。日付・遷移先・一覧内のレースIDを検証し、別日のリンクや一般ナビゲーションを混入させない。
- 当日・未来日の一覧未確認を、過去結果の月間索引で補完完了にしない。途中まで終了したレースだけで全日完了と扱うことを防ぐ。
- 現在用HTMLの有効期間を短くし、既存の長期キャッシュ／再開記録にも取得時刻を適用する。空・不適合なキャッシュの場合は同じURLを一度だけ新しく確認する。
- 結果ページがまだない直近のレースでは、既存の出馬表取得へ接続する。出馬表自身の日付・レースIDを確認し、着順や走破タイムを作らない。
- 不成功のジョブに安全な日本語の `failure_reason` と分類を保存し、完了状態・永続化・状態APIを通して保持する。レスポンス本文、認証情報、任意の例外文字列は画面に渡さない。
- 予測画面に理由と再試行ボタンを残す。部分取得済みのレースは確認できる。DBの読み込みエラーを単なる未取得として扱わない。

通信の共有間隔・同時数・403/429時の停止制御は維持する。アクセス制限の解除、プロキシの変更、特徴量や品質基準の緩和は行わない。

## 検証上の制約

公開サイトでは当日の出馬表の存在を確認したが、ローカルの共有通信経路ではPC版・モバイル版ともHTTP 400が返った。したがって、取得先との実通信による成功は別途確認が必要であり、修正だけで通信拒否の解消や本日データの保存を保証するものではない。

現在一覧のHTMLテストは契約を検証する合成fixtureであり、取得成功した実HTMLの再生ではない。不明なHTMLは空の開催日として確定せず、未確認として表示する。
