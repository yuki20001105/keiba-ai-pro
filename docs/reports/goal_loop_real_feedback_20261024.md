# 実データ goal-loop 実行・改善フィードバック

> 続報（2026-10-25）: 年間1,000万円換算、レース別傾斜配分、年別欠損・取得証跡の詳細は
> `docs\reports\goal_allocation_quality_20261025.md`。

## 目的と判断の境界

目的は「実データで学習・評価し、課題を実装修正へ戻し、同条件で再評価して証拠を残す」。
改善や黒字化を保証するものではない。本番モデル、購入条件、元DBは変更しない。
入口は `scripts\run_model_goal_loop.py`。ネイティブの `/goal` コマンドを実行したという意味ではない。

実データで2回、再実行を含む9試行・27回の年別fitを完了した。
第1回は改善なし。欠損診断と検証処理の重複を修正した第2回では、
ランキング方式が開発期間内の改善候補となった。
順位相関は **0.465831 → 0.499276**、1位指名的中率は **24.71% → 27.18%**。
ただし参考損益は依然赤字であり、未知期間の合格・本番採用は達成していない。

## 固定した実験条件

| 項目 | 内容 |
|---|---|
| 元データ | ローカルSQLiteの独立スナップショット |
| データ選択 | 既存の中央平地・完全出走馬集団の適格性ルール |
| 全保存データ | 延べ458,095頭・32,826レース、2016-01-05〜2026-10-17 |
| 診断範囲 | 2016〜2025年、延べ424,323頭・30,380レース |
| 評価範囲 | 2023〜2025年、延べ125,421頭・9,072レース・322開催日 |
| 時系列分割 | 各評価年の前年末までで学習。2016年から履歴を使用 |
| 特徴量 | 対照は既存安全特徴量72列。当該オッズ・人気・結果は入力しない |
| 主指標 | レース平均Spearman順位相関。AUCや的中率とは別物 |
| 採用候補条件 | 改善差0.001以上、年別・1位的中率の非劣化、日単位bootstrap区間下限が正 |
| 制限 | CPU 1ワーカー・4スレッド、各年200ラウンド、各Campaign最大2時間 |
| 未知期間 | なし。2023〜2025年は既知の開発期間。2026年の精度は測定しない |

第2回は第1回の凍結済みDBを入力にした。両者の `dataset_sha256` は
`225fc165d8289beed7e49c2774b3c04988ba959c25c452ce003d827b5d0dcc23` で一致する。
対照は同条件で再学習したモデルであり、稼働中の本番モデルではない。

## 実データの課題を受けて変更した実装

### 欠損理由の誤分類

従来は「過去出走数が0か」だけで履歴系の欠損を分類していた。
前々走には2走、同条件の率には当該条件の観測件数が必要であり、同じ判定では不十分だった。
`goal_diagnostics.py` を特徴量ごとの観測件数に基づく判定へ変更した。

| 特徴量 | 欠損行数 | 修正前の原因不明 | 修正後の原因不明 | 修正後の自然欠損 |
|---|---:|---:|---:|---:|
| 前々走着順 | 91,210 | 43,830 | 0 | 91,210 |
| 同競馬場・馬場の勝率 | 202,176 | 202,176 | 0 | 202,176 |
| 父の勝率 | 105,344 | 105,344 | 104,522 | 822 |
| 母父の勝率 | 105,833 | 105,833 | 104,522 | 1,311 |

自然欠損は「選択済みデータ内に必要な過去観測がない」という意味であり、
実際の新馬・全履歴取得済みを保証しない。IDや件数が不明・不正なら原因不明を維持する。
過去走があっても上がりタイムだけ欠損していれば、自然欠損とは断定しない。
NaNの値やモデル入力は変更しておらず、診断の訂正を予測精度向上とは呼ばない。

### 実行時間の改善

実測では候補の学習が約59〜65秒なのに対し、終了後の重複検証が約128秒かかっていた。
各試行で既に独立再計算したレース別記録を同一run内で再利用するよう変更した。
完了時は全試行を改めて検証し、途中の成果物改変を検出する境界は維持した。
候補の結果保存から比較判断までの中央値は **128.0秒 → 40.7秒**、約68%短縮。
対照の予測ファイルハッシュと全評価指標は修正前後で一致した。

## 特徴量とデータ取得への具体的なFB

対照の学習データ内サンプルSHAP上位は、レース格、同馬場の過去3着内率、
馬場状態、月、過去10走平均着順だった。レース格等はレース間の速度差も説明するため、
この順位を「レース内で勝ち馬を当てる重要度」と同一視しない。
相関の絶対値0.9以上は35ペア。過去3・5・10走の件数と観測割合はほぼ同じ情報で、
前走の距離とタイムも高相関だった。削除は別の比較実験で確認する。

血統ID相当の情報不足は104,522行、25,177頭に残った。
読取専用の照合では、正規化済み `horse_details` に補完可能な該当行は0、
既存のローカル血統キャッシュには父・母父それぞれ30,608行分が見つかった。
キャッシュ存在は現在の補完可能性であり、当時の取得時刻や公開状態の証明ではない。

したがって、25,177頭を直ちに再スクレイプするのではなく、先に既存キャッシュと
埋込JSONの整合・利用可能時刻・出典を確認する。今回は読み取り照合のみで、
元DBの補完、キャッシュの本番反映、外部への追加リクエストは行っていない。

## 第2回の再評価

Campaign: `reports\generated\model-experiments\goal-real-20261024-v2`

修正コードを新しいソース契約へ固定し、上記欠損件数の訂正とデータハッシュ一致を確認。
各仮説1試行・計4試行に絞り、停滞上限を3仮説として、
正則化・特徴量グループ除去・ランキング方式をすべて確認する。
採用閾値、評価年、モデルラウンド数は緩和していない。

4試行・12回の年別fit、約10.0分で計画どおり終了し、独立検証に合格した。
試行数も異なるため、Campaign全体の時間差を実装改善だけの効果とは扱わない。

| 試行 | 方式・変更 | 順位相関 | 1位的中率 | 参考回収率 | 判定 |
|---|---|---:|---:|---:|---|
| baseline | 速度偏差回帰 | 0.465831 | 24.71% | 77.31% | 対照 |
| p00-t00 | 正則化 | 0.459768 | 24.22% | 77.76% | 棄却 |
| p01-t00 | 条件適性等の除去 | 0.459259 | 24.82% | 79.27% | 棄却 |
| p02-t00 | LambdaRank、同じ72特徴量 | **0.499276** | **27.18%** | 78.02% | 開発内の改善候補 |

候補の順位相関差は **+0.033445**。322開催日を対にした100回bootstrapの95%区間は
**[+0.030697, +0.035777]**。1位的中率差は+2.47ポイントで、
固定済みの改善・年別非劣化・1位的中率非劣化の条件を満たした。
NDCG@3も0.776374から0.790817へ改善した。

| 評価年 | 対照の順位相関 | ランキングの順位相関 | 差 |
|---|---:|---:|---:|
| 2023 | 0.462359 | 0.497396 | +0.035037 |
| 2024 | 0.469659 | 0.500517 | +0.030858 |
| 2025 | 0.465524 | 0.499932 | +0.034408 |

この区間は既知の開発データ内の記述的な比較で、多数試行による選択バイアスや
未知期間への汎化を証明するものではない。順位相関を優先したので、
参考回収率が最も高い特徴量除去モデルを選ぶ、といった結果依存の基準変更もしていない。

候補モデルは第2回の `trials\p02-t00\artifacts\fold_2023.joblib`、
`fold_2024.joblib`、`fold_2025.joblib` に保存した。
いずれも年別評価用bundleであり、2025年foldは2024年末までの学習。
全開発期間で最終再学習した本番モデルではない。
今回はLightGBM内の速度偏差回帰とランキングを実データで比較した。
勝敗分類は実装済みだが今回の実データ比較には含めず、CatBoost/XGBoostも未検証。

## 本番判断と次の優先順位

対照の1位指名的中率は24.71%、最終1番人気の参考値は33.69%。
対照の各レース単勝100円の参考回収率は77.31%、純ROIは-22.69%だった。
改善候補でも参考回収率78.02%、純ROIは-21.98%であり、
順位・的中率の改善は今回の条件では黒字化につながっていない。
これは期待値1.2条件付きの承認済み購入ルールではなく、購入時点の市場も再現していない。
入力情報も異なるため、この比較だけで市場超過収益を証明・否定しない。

順位相関の開発内改善があっても勝率校正、未知期間、時刻付き市場情報、
正式購入ルール、受入契約の評価を通るまでは本番採用しない。
優先順位は、血統キャッシュの出典付き整合確認、ランキング得点と勝敗分類の比較・独立期間での確率校正、
新たな未観測期間での前向き評価。その後に別モデルライブラリを比較する。

証拠の正本は各Campaignの `verification.json`、`decisions`、`trials`、`progress`。
欠損・学習内SHAP・年別成績・参考損益は同ディレクトリの `dashboard.html` に保存する。
第1回の検証は当時の旧ソース契約の記録であり、修正後コードで旧契約を再検証する操作は拒否される。
