## 1. カラムはどこにあるか

`race_results_ultimate` は、出走馬ごとの情報を `data` というJSON文字列に保存する。
父はその中の `sire`、母は `dam`、母父は `damsire` であり、
この実行で独立したSQLカラムを追加したわけではない。
今回欠けていた6頭は、空文字が入っていたのではなく、これらのキー自体がなかった。

SQLで確認する場合:

```sql
SELECT json_extract(data, '$.horse_number') AS horse_number,
       json_extract(data, '$.horse_name') AS horse_name,
       json_extract(data, '$.sire') AS sire,
       json_extract(data, '$.damsire') AS damsire,
       json_extract(data, '$.sire_id') AS sire_id,
       json_extract(data, '$.damsire_id') AS damsire_id
FROM race_results_ultimate
WHERE race_id = '202506050811'
ORDER BY horse_number;
```

研究用DBは後述の成果物ディレクトリにある `research.db`。
本番DBで同じSQLを実行しても、今回の補完は反映されていない。

`safe_sire_starts` 等はモデル用に生成する派生値で、父の名前やIDそのものではない。
父の場合は、対象となる過去の産駒出走記録の累積件数。
父自身の生涯出走数でもない。母父も同様に、対象馬群の先行記録から算出する。

## 3. 何を修正したか

以前は、別の過去行に和英混在・国表記付きの親名があるだけで、
その馬の完全に空の行まで補完を保留していた。
今回は名前の表記を推測せず、血統ページの子馬IDと親馬へのプロフィールリンクID、
5代血統表の位置を照合する別の研究用補完処理を実装した。

- 空の行は、子馬と父・母・母父の出典付きIDが確認できた場合だけ補完する。
- 同じ行の既知の名前・別名キー・親IDが矛盾する場合は保留する。
- 別の行にある旧表記は変更せず、翻訳名と英語名が同一だと推定もしない。
- 複数の出典で親IDが異なれば保留する。同じIDでも表記の違いを全体へ展開しない。
- 結果・着順・オッズなどの非血統値は変更しない。

既存の厳しい名前判定は緩めていない。新たな親IDは出典情報であり、
モデル側の集計キーを名前からIDへ全面移行した実装でもない。
同じ親の異なる名前表記が集計を分断する問題は、別途残る。

リダイレクトなし、制限時は停止とした。

残る73,297行は17,960頭に対応し、今回確認した共有キャッシュには
当該馬の血統HTMLがなかった。取得失敗・提供元にも情報がない、と確定したわけではない。
**残る17,960頭すべてを今回新規取得したわけではなく、全経路を尽くした結果でもない。**
まずは未保存血統の段階的取得が残る。元ページに親がない／矛盾する場合も、
取得不能と断定する前にその証拠を個別に残す必要がある。

観測履歴不足等の欠損が116セル減ったのは、親名が判明して血統集計の参照対象が
変わったためで、馬自身の過去走を新規取得した結果ではない。
初回観測や必要な過去記録がない率・平均を、数値0で埋めてはいない。
公開元にも空欄だった上がり時計の問題も、この血統補完では解決していない。
