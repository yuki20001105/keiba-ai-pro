## 2. 21セルのうち12セルを復元できた理由

### 2.1 原因は通信失敗ではなく、学習対象と履歴参照対象の共用

**正常に完走した馬の着順・時計は保存されていたが、同じ過去レースの別の馬に
数値の着順・時計がないため、そのレース全体が履歴からも除外されていた。**
この12セルは「公開元に値がなかった」のではなく、「ある過去実績を集計しなかった」欠損である。

処理は次の順序だった。

```text
過去レースの全出走馬
  → 学習の目的変数を作れない馬だけを除外（target_missing）
  → 全頭が残らないレースを、実験用データセットで丸ごと除外
  → その残りだけで過去履歴を生成
  → 正常に完走した別の馬の過去実績も参照できなくなる
```

今回の学習対象は `speed_deviation` であり、数値の着順と正の走破秒数が必要。
元ページと保存JSONの双方を再照合すると、除外のきっかけは次の出走馬だった。

| 過去レース | 目的変数を作れなかった馬・元ページの着順表記 |
|---|---|
| 2023ホープフルS | タリフライン `中`、ゴンバデカーブース `取`、サンライズアース `取` |
| 2024皐月賞 | ダノンデサイル `除` |
| 2024東京優駿 | メイショウタバル `取` |
| 2024有馬記念 | ドウデュース `取` |

`取` は取消、`除` は除外、`中` は競走中止の表記。
これらの行は走破時計も空欄であり、数値の学習対象にできないこと自体は問題ではない。
**別の正常な完走馬まで履歴から落ちることが、今回復元できた欠損の原因**だった。

| 過去レース | 保存行数 | 学習対象の適格行数 | 学習対象から落ちる行の理由 |
|---|---:|---:|---|
| 2023ホープフルS `202306050911` | 18 | 15 | `target_missing` 3行 |
| 2024皐月賞 `202406030811` | 18 | 17 | `target_missing` 1行 |
| 2024東京優駿 `202405021211` | 18 | 17 | `target_missing` 1行 |
| 2024有馬記念 `202406050811` | 16 | 15 | `target_missing` 1行 |

現行の凍結実験契約は、学習対象に欠ける出走馬があるレースを全体で除外する。
この制約を履歴にも共用していたため、残る正常な馬の過去実績まで集計から消えていた。
全頭が揃う学習対象を作る制約と、検証済みの過去実績を参照する制約を分ける必要がある。
根拠となる実装は `training\eligibility.py` の `_target_valid_mask` と、
`experiments\dataset.py` の `partial_races` 除外から `engineer_features(clean)` までの処理。

### 2.2 復元した12セルの内訳

今回は4つの元結果ページの日付・全馬の馬番／馬ID／馬名を照合し、
対象の6過去走について着順・走破時計がDBと一致することも確認した。
**学習対象の集団を変更せず、1レース研究用の条件別履歴だけ別契約で補完**した。
対象レース当日以降の結果は参照しない。

| 馬 | 条件 | 復元に使った過去レース | 集計上の参照走数 | 復元セル数 |
|---|---|---|---|---:|
| メイショウタバル | 中山・芝 | 2024皐月賞17着 | 0→1 | 3 |
| サンライズジパング | 中山・芝 | 2023ホープフルS3着、2024皐月賞9着 | 0→2 | 3 |
| サンライズジパング | 長距離帯 | 2024東京優駿12着 | 0→1 | 3 |
| レガレイラ | 長距離帯 | 2024東京優駿5着、2024有馬記念1着 | 0→2 | 3 |

各行で復元したのは、勝率・3着以内率（複勝圏率）・平均速度の3特徴量。
したがって **4条件×3指標＝12セル**。参照出走件数も更新したが、
件数はもともと0という非欠損値だったため、「復元した欠損12セル」には数えない。

例えばレガレイラは、長距離帯の履歴が集計上0走だったが、確認できた過去走は2走。
その2走から勝率1/2、3着以内率1/2と平均速度を算出できる。
同条件の実績を持たない他馬の値を借りた補完ではない。

履歴件数も対応する確認済み件数へ更新した。既存の非欠損特徴量を一括再集計したり、
同じ条件でない記録から平均を代用したりはしていない。
凍結元の学習データ、本番特徴量、本番DB・モデルは変更していない。
改善後の値は、別成果物 `race-features.csv` にある1レース用の研究データである。

## 3. 残る9セルは、同条件の過去出走がなく統計が未定義

### 3.1 「同条件」と計算式

今回の特徴量では、次の2種類を別々に集計する。

| 特徴量の接頭辞 | 今回の条件 | 条件に含まないもの |
|---|---|---|
| `safe_horse_course_*` | 同じ馬の中山・芝 | 距離の一致 |
| `safe_horse_distance_band_*` | 同じ馬の2300m以上の距離帯 | 開催場、芝・ダートの一致 |

長距離帯は2500m完全一致ではなく、現行実験の距離区分 `long`（2300m以上）。
参照日は必ず `source_race_date < target_race_date` とし、当該有馬記念は含めない。

```text
n = 確認できた同条件の過去出走件数
勝率       = 1着件数 / n
3着以内率  = 3着以内件数 / n
平均速度   = Σ(各過去走の距離 / 走破秒数) / n
```

`n = 0` なら、どの統計も計算できずNaNとなる。
これは数値上は欠損だが、取得失敗による原因不明の欠損とは異なる。

### 3.2 DBにないだけでなく、公開成績も確認した根拠

現在のプロフィールHTMLだけでは過去成績表がないことも確認した。
ページ内のJavaScriptは、公開取得先
`https://db.netkeiba.com/horse/ajax_horse_results.html`
へ `input=UTF-8`、`output=json`、`id=馬ID` を付けて成績表を読み込む。

この公開Ajax経路を使う検証用処理を追加した。
3頭のプロフィールとAjax応答を取得し、子馬ID・応答・公開通算件数との一致を確認。
表の行数はそれぞれ9／16／24行でプロフィールの通算件数と一致した。
全表示記録から当該有馬記念および後日の出走を除き、次を確認した。

| 馬 | 当該レース前の表示記録数 | 同条件の記録 | 残る欠損 |
|---|---:|---|---:|
| エキサイトバイオ | 8 | 中山・芝0走 | 勝率／複勝圏率／平均速度の3セル |
| アドマイヤテラ | 11 | 中山・芝0走 | 同3セル |
| エルトンバローズ | 18 | 2300m以上0走 | 長距離帯の同3セル |

これは、照合した公開成績上の確認であり、未知の別提供元まで調べ尽くしたという意味ではない。
ただし、現行定義で分母となる同条件の過去出走が0なので、率・平均は算出できない。
出走件数0は正しい値だが、「未経験」を勝率0・速度0へ置き換えるのは誤りである。

例えば、メイショウタバルの中山・芝は「1走して未勝利」なので勝率0を計算できる。
エキサイトバイオの中山・芝は「0走」なので勝率を計算できない。
この2つを同じ0にすると、未経験と実績上の未勝利を混同する。
残る3頭は各3指標が未定義なので、**3頭×3指標＝9セル**となる。

Ajax取得は「静的HTMLだけでは成績表を読めない」という取得経路上の問題を解消した。
しかし、確認後も同条件の出走が0なので、この9セルを実測値で埋める効果はなかった。
**取得経路の問題と、同条件未経験による未定義は別の理由**である。

この9セルを数値で必ず埋めるには、近い条件へのバックオフや事前分布など、
別のモデル設計・学習内検証が必要になる。それは実測値の再取得ではない。
今回、そのような補完を勝手に導入して「全72特徴量の欠損0」とはしていない。

## 4. 段階判定と次の境界

1. **父名・母父名の欠損0:** 合格。
2. **今回の72特徴量で欠損だった21セルの原因追跡:** 集計から落ちた実績による12セルを研究用補完で復元。同条件未経験による9セルは公開履歴で理由を確認。
3. **全72特徴量のNaNそのものが0:** 未達。上記9セルは定義上未算出。
4. **2016〜2026年への展開:** 停止中。1レースの成功を全期間の欠損0の保証にしない。

### 4.1 「原因確認済み」と「数値欠損0」は別の合格条件

| 判定 | 今回の結果 | 意味 |
|---|---:|---|
| 原因未説明のモデル特徴量欠損 | 0セル | 当初の21セルすべてに根拠を付けられた |
| 数値として残るモデル特徴量欠損 | 9セル | 理由が分かっていてもNaNは残る |
| 父名・母父名の欠損 | 0セル | 名前の確認であり、全親ID移行の合格ではない |

原因未説明0は、この1レースの72特徴量に限定した結果。
生JSONの全キーや全期間について、原因不明が0になったという意味ではない。
`stage-acceptance.json` でも原因未説明は0、全72特徴量の欠損0判定はfalseと分けて記録している。

### 4.2 全期間へ展開する前に整理する仕様

以下は推奨する次段階の受入条件であり、旧契約・稼働処理へ適用済みではない。

| 項目 | 次段階の条件 |
|---|---|
| 取得・保存不備 | 元ページの出典付き取得で修復し、未解決を理由・対象付きで残す |
| 履歴参照 | 学習対象の選別と切り離す。別の馬の取消等だけで正常な履歴を捨てない |
| 履歴の安全性 | 日付・馬ID・レース条件・結果・出典を確認し、重複・矛盾・当日以降の結果を除外する。単に除外レースを全復活させない |
| 同条件0走 | 件数0と、率・平均のNaNを保持する。初条件という理由を明示し、取得不備と分ける |
| 本番展開 | 別契約で対象・集計条件・欠損許容条件を固定し、学習・評価・正式受入を通す |

既定の方向性は、**「解消可能な取得・処理不備を減らす」「残るNaNの理由を明示する」**
ことであり、未経験の率・平均まで再取得で数値化できるとはしない。
数値NaNを一律0個にする要件を維持するなら、再取得とは別に推定補完の設計・検証が必要。
その設計変更を、今回の12セル復元の成功だけで承認した扱いにはしない。

今後全期間へ展開する場合も、取得不備・履歴選別の影響・真の初条件を分ける。
Ajax成績表の取得は今回の検証経路で確認したもので、稼働中の全スクレイパーに
反映済みという意味ではない。元の学習集団やモデル契約を変更する際は別の契約を作る。

## 6. 承認後の研究用モデル入力補完

### 6.1 補完規則と適用範囲

利用者の「AIに学習させやすいように補間する」という指示を受け、
時系列上の線形補間や一律0埋めではなく、**同じ馬の広い条件の過去集計へのバックオフ**を追加した。

| 項目 | 研究用契約 |
|---|---|
| 対象 | 公開履歴の照合で同条件未経験と確認した3頭・9セルだけ |
| 補完元 | 同馬の `safe_horse_surface_win_rate` / `top3_rate` / `avg_speed_mps` |
| 条件 | 対象条件の出走数0、対応セルがNaN、補完元の出走数が正の整数、補完元が有効な率・速度 |
| 識別 | 条件別6指標それぞれに `_was_imputed` 列を追加。推定値1、実測集計値0 |
| 保存 | 元のNaN・馬ID・出走数0を別成果物に保持し、各推定値の補完元列・集計件数・理由を記録 |
| 禁止 | 当該レースの結果、当日以降の成績、最終オッズ、対象期間全体から算出した平均・中央値の使用 |
| 不明・取得失敗 | 事前に確認・承認した欠損セルと一致しない場合はエラー。黙って補完しない |
| 全く過去走がない場合 | 補完元もないためエラー。学習期間だけから決める事前値等の別設計が必要 |

補完元は、凍結済み研究集団に含まれる過去走の芝・ダート別集計であり、
公開プロフィールにある全生涯成績の集計ではない。今回、補完元の集計範囲を変更していない。
例えば中山・芝未経験でも芝全体の経験はあり、その成績を中山・芝での推定入力として使用する。
これは中山実績の復元でも、そのレースの校正済み勝率でもない。

### 6.3 結果・証拠と次の境界

新しい成果物:
`reports\generated\data-quality\feature-gap\arima-structural-imputation-v1`

- `contract.json`: 72値特徴量＋6フラグの78列、補完規則、入力・コードのハッシュ。
- `observed-features.csv`: 補完前の16頭の値と9セルのNaNを元ファイルと同じバイト列で保存。

16頭×72値特徴量の欠損は**9→0**、追加6フラグにも欠損はない。
