# KeibaAI 目的変数の比較・採否

2026年11月1日。6方式を同じ入力・時系列条件で38回学習した。
**単一モデルの置換は見送り、現行方式を維持する。**
勝敗二値モデルは勝率推定を改善したが、後段評価の全順位相関が事前許容値を超えて低下した。
本番モデル・DB・購入条件は変更していない。

**この維持判断は暫定的な運用判断であり、「距離・芝ダだけの基準が最適」という結論ではない。**
6方式比較は、基準のくくりだけを変更した比較ではない。
競馬場・馬場・天候を補正しない方がよいと証明したものでもない。
基準の分類について確認できた範囲と未検証事項は第9節に整理する。

## 1. まず何を予測するか

「条件に対する走力」「勝ち馬」「上位の着順」は同じ目的ではない。
速度偏差は定義可能な教師値だが、そのまま純粋な能力や勝率を意味しない。
今回の固定目的は **校正済み勝率のNLL改善と、レース内順位の維持** とした。
違う目的変数のRMSEを横並びにして選定していない。

表示用と学習用の基準も異なる。
`routers\dataframe.py` の表示は開始日より前365日以内の適格データを読む。
`training\db_shared_optimized.py` の現行学習はTRAIN全体から基準を作る。
`speed_deviation.py` のfit関数自体に365日制限はない。
表示例の42,358頭を、今回の学習件数として流用していない。

## 2. 現行方式の課題

- 距離・芝ダ別の30頭未満を全距離・全芝ダの平均へ切り替えるため、疎な条件で不連続になる。
- 場・馬場・天候を補正しないため、能力と条件による速さが混ざる。
- 基準統計と通常の回帰損失は出走行単位なので、多頭数レースの寄与が大きい。
- 勝敗・順位を直接学習せず、速度の予測を勝率や順位へ変換している。
- クラス補正を単純に追加すると、強いクラスの能力差まで消す可能性がある。
- ペース、不利、当日の風・馬場差等は今回の公開入力だけでは分離できない。

現在レースの走破タイム・着順は教師・評価にのみ使う。
現在レースの入力には含めない。欠損時計を0速度へ変換せず、適格な完全レースを共通対象とする。

## 3. 比較した6方式と計算式

### A. 現行速度偏差

`v_i = 距離_i / 走破秒_i`

`y_i = (v_i - μ_距離・芝ダ) / σ_距離・芝ダ`

TRAIN全体で平均・標準偏差をfitする。適格グループは30頭以上、
標準偏差は標本標準偏差。未成立グループは現行の全体基準を使う。
これは今回の同条件対照であり、使用中joblibの成績そのものではない。

### B. 現行教師値＋レース均等損失

教師値はAと同じ。学習の行重みだけ変更する。

`w_i = TRAINの平均出走頭数 / そのレースの出走頭数`

各レースの総重みが等しく、全行の平均重みが1になる。
固定L2の実効強度を大きく変えないため、単純な`1/頭数`をそのまま学習へ渡さない。
基準統計の方式は変えず、損失重みの効果を切り分ける対照である。

### C. 過去365日の条件補正パフォーマンス

これは外部Speed Figureの再現ではなく、新しく定義した研究指標。

1. `s_i = log(距離_i / 走破秒_i)`、`x_i = log(距離_i / 1600)`。
2. 対象日をtとして、**`t-365日 <= 履歴日 < t`** の結果だけを使う。
   同日結果・未来結果は基準に使わない。
3. 履歴内の各出走馬の重みを`1/そのレースの頭数`とする。1レースの総重みは1。
4. 芝・ダートを分け、加重最小二乗で親曲線`μ_P(x)=a+b×x`をfitする。
   親分散`σ_P²`はこの曲線に対する加重残差分散。距離の変動がない場合は傾き0。
5. 「芝ダ・距離・競馬場・馬場状態・天候」が同じ細分類の加重平均`μ_F`と
   加重分散`σ_F²`を求める。細分類の重み合計`W_F`は完全レース相当数。
6. `λ = W_F / (W_F + 20)`、`μ = λμ_F + (1-λ)μ_P(x_i)`。
7. `σ² = max(λσ_F² + (1-λ)σ_P² + λ(1-λ)(μ_F-μ_P)², 0.005²)`。
8. `y_i = clip((s_i-μ)/sqrt(σ²), -5, +5)`。

細分類の履歴がなければλ=0として、同じ芝ダの距離曲線を使用する。
芝ダの親が30レース相当未満なら未定義とし、他の芝ダの全体平均へ切り替えない。
クラスは一律除去しない。クラス差と条件差を完全に分離できた指標ではなく、
**過去の条件に対して速かったパフォーマンス**と解釈する。
縮約20・尺度下限0.005・±5は事前固定値であり、全設定を探索した最適定数ではない。

### D. レース内相対速度

`y_i = (v_i - そのレースの平均速度) / そのレースの標本標準偏差`

例えば16・15・14m/sなら平均15、標準偏差1で、教師値は+1・0・−1。
全頭の速度が同じなら0。これはレース内の相対的な走りであり、
異なるレース間の絶対能力を直接比較する指標ではない。
現在レース全頭の時計を使うのは教師作成時だけで、予測時には使わない。

### E. 勝敗二値

`y_i = 1着なら1、それ以外は0`

LightGBM二値損失で学習する。回帰方式B～Dと同様、平均1のレース均等行重みを使う。
推論の生スコアfから、独立CALのみで温度Tをfitする。

`p_i = exp(f_i/T) / Σ_全出走馬 exp(f_j/T)`

Tはレース平均NLLを最小化する1パラメータ。候補馬だけでなく全出走馬で和1にする。
生スコアや単純sigmoidを、そのまま校正済み勝率とは呼ばない。
今回の確率は結果確率の履歴評価であり、購入オッズ取得・期待値の受入証跡ではない。

### F. 上位3着重視ランキング

`relevance_i = max(4-着順_i, 0)`。1・2・3着が3・2・1、それ以外0。
LightGBMの既定gainは7・3・1・0。レースをqueryとしてLambdaRankで学習し、
打切り位置3・内部query正規化を使う。
生スコアはEと同じCAL-only温度校正で比較する。
これは三連単の順序付き確率を直接学習・校正したものではない。

## 9. 速度の基準をどのくくりにするか

### 9.1 現行の「プラス・マイナス」の意味

現行は、学習対象の全速度を常に一つの平均へまとめる方式ではない。
まず「距離・芝ダ」が同じTRAINの適格な出走馬から平均・標本標準偏差を作る。
例えば東京芝1600mと阪神芝1600mは、競馬場や天候にかかわらず同じ基準に入る。
30頭未満または標準偏差が成立しない場合だけ、TRAIN全体の基準へ戻る。

`y = (その馬の実測速度 - そのグループの平均速度) / そのグループの標準偏差`

正負は基準より速い・遅いことを表す。値は速度差そのものではなく標準偏差の数。
入力特徴量に競馬場・馬場・天候があっても、目的変数の平均がそれらで補正済みとは限らない。
実装の正本は`keiba\keiba_ai\speed_deviation.py`の
`_group_keys`、`fit_speed_deviation_baseline`、
`apply_speed_deviation_baseline`である。
現行46特徴量学習は`training\db_shared_optimized.py`でTRAINだけからfitしている。

### 9.2 今回の条件補正で分類したもの・していないもの

| 基準に含める項目 | 現行A | 研究C |
|---|---|---|
| 芝・ダート | 分ける | 分ける |
| 距離 | 距離ごとの平均 | 芝ダ別距離曲線と細分類 |
| 競馬場 | 分けない | 細分類に含める |
| 馬場状態 | 分けない | 細分類に含める |
| 天候 | 分けない | 細分類に含める |
| その開催日の固有の馬場差 | 推定しない | 推定しない |
| 内外・A/Bコース、含水率、風等の独立補正 | しない | しない |

Cの細分類は「芝ダ・距離・競馬場・馬場状態・天候」の同時組合せである。
履歴が少ないと同じ芝ダの距離曲線へ縮約する。競馬場別、馬場別を順に経由する
多段階の基準ではなく、それらの分類を個別に追加した効果も比較していない。
同日結果はCの履歴から除外しており、当日のトラックバリアントを推定する実装ではない。
Dは同じレース内で標準化するが、レース間の能力比較とは別の目的変数である。

### 9.3 細かく分けるだけでは不安定になる

凍結した共通対象の2024年、2,994レースを使い、各レースを1件として記述集計した。
新しい学習・採否評価ではなく、分類の疎さを確認するための集計である。

| 分類 | グループ数 | グループあたりレース数の中央値 |
|---|---:|---:|
| 芝ダ・距離 | 28 | 45 |
| ＋競馬場 | 98 | 24 |
| ＋馬場状態 | 255 | 5 |
| ＋天候 | 527 | 2 |

最後の分類では527群中486群が年間20レース未満で、その群に1,760レースが属する。
これはCの各対象日時点の365日履歴数や、現行の30頭判定そのものではない。
全保存データ・全中央レースの集計とも呼ばない。
それでも、細分類ごとの平均・標準偏差を独立に採用する方式が不安定になり得ることは分かる。
環境を考慮するなら、データ量に応じた縮約や親基準への戻し方も必要になる。

### 9.4 当日の環境と基準の採否は未確定

同じ競馬場・距離・芝ダでも、馬場状態や風等によって速度が変わり得るため、
条件付きの走行性能を定義する際に環境差を検討する方向は妥当である。
ただし、天候分類だけではその日の馬場差を表せない。
クラス、ペース、出走馬の強さも分類ごとに異なり、分類を増やすだけで能力と環境が分離するわけではない。

「その日」の全出走馬平均をそのまま基準にすると、当日のレース構成や対象レース自身の
強さまで差し引く可能性がある。日付で細分するだけでなく、他レースからの環境効果の推定、
対象レースの除外、データ不足時の縮約を別途設計・検証する必要がある。
レース後に教師値を作ることと、発走前の入力へ当日結果を渡すことは別であり、
未発走時点で未知の結果から作った補正値を予測入力や購入判断へ渡してはいけない。
今回のCはこの当日補正を実施していない。

**既存のままでよいと確認できていない。基準の最適なくくりも未確定である。**
くくりを判断するには、速度の変換、基準期間、重み、縮約・尺度設定、
入力、学習・校正・評価期間をそろえ、距離・芝ダ、競馬場追加、馬場追加、天候追加を
差分比較する必要がある。これは今回の6方式比較には含まれていない。
異なる教師値のRMSEだけで採否を決めず、同じレース集合で勝率・順位の影響を確認する。
今回の維持はその比較が不要という意味ではなく、代替モデルの受入未達による暫定維持である。

その後、大分類だけを変えた4方式を別の凍結実験で比較した。
結果・選定は`speed_baseline_grouping_comparison_20261101.md`を参照。
本書の6方式比較や凍結成果物を差し替えたものではない。
