# データ取得方法・全項目の欠損監査

## 結論

**現在の取得方法だけでは、学習用の全履歴を十分にそろえられていない。**
レース本体の取得、現在プロフィール・Ajax成績表の取得、血統の出典確認は改善したが、
「過去成績の一覧を取った」と「その過去レースの全結果が学習に使える」は別である。
今回、取得済みなのに使えなくなっていた正常な過去走をさらに91件復元した。

**全データの欠損0は未達。** 取得で直せる欠損、実績がないため計算できない統計、
公開元が値を出していないもの、まだ公開元と照合していないものを分ける。
公開元の未経験を確認したケースはあるが、未照合のセルを一律に初出走とは判断しない。

## 2. 主な課題と、再取得で直るか

| 課題 | 実際に確認したこと | 必要な対応 |
|---|---|---|
| 過去結果が学習へ入らない | 公開表の8過去走リンクが、選択履歴にない。6レースのデータ自体はDBに存在 | 一覧のリンクから全結果を照合し、保存・品質・利用可能性を確認する |
| 他馬の欠落で正常走まで除外 | 6レースで他馬の明示的な非完走状態が保存時に失われていた | 元の結果ページの状態を復元し、全馬を通常の品質判定へ通す。今回は91走を復帰 |
| 初出走・直近2走目の不足 | 追加99頭中79頭は公開出走数と照合でき、対象日前の出走0を確認 | 過去実績は再取得しても作れない。モデル入力の推定とフラグを別契約で扱う |
| 地方経験を現在の学習範囲に含めていない | 2頭に地方の20過去走が存在 | 「未経験」としない。中央平地の契約を維持し、地方を含む場合は別の範囲・特徴量契約を作る |
| 公開件数が一致しない | 13頭のプロフィールで通算数と表の行数からの照合が不一致 | 空着順を取消と推測して引かない。対象日前の状態不明と、後日の不一致を区別して追加照合する |
| 一時的な通信不成立 | 追加100頭中1頭のプロフィール取得がstatus=0 | 未取得として残し、共有待機・停止規則に従う再試行対象とする |
| 上り時計そのものが空 | ゴーゴーコクラの公開過去結果で上り欄が空。3つの平均項目に影響 | 同じページの再取得だけでは時計は増えない。別の合法な出典、または推定を検討。0秒にはしない |
| 血統が1提供元で得られない | マンタナのnetkeiba専用表は親セルが空。通常プロフィールにも利用できる血統欄がない | 別の一次資料を照合する。「血統が存在しない」ではない。JBISで3親を確認済み |
| 過去条件が保存履歴にない | 芝・ダート・距離帯・競馬場別の出走数が0 | 公開の全過去走と照合するまで真の初条件と断定しない。既存の同馬同馬場バックオフは推定として保持 |
| 保存済み直近成績に当日・未来が混ざる | `prev`は207,032行、`prev2`は194,540行に対象日以降の日付 | これらを過去予測入力に使わない。72安全特徴量は別途、対象日前のDB履歴から再生成する |

## 6. 今後の取得経路の必須条件

1. 公開プロフィール・Ajaxを子馬IDと対象日付きで取得し、当日・未来を排除する。
2. 一覧の過去レースIDをDB結果・品質・利用履歴と照合する。直近2走だけで全履歴取得完了にしない。
3. 未利用の中央結果は全馬の元結果を確認し、正常走を巻き添え除外している原因を修復する。
4. 地方・海外・2013年以前は現在の履歴契約の外として残す。取り直しても現契約で使えない理由を表示する。
5. 血統の別出典は子馬照合、親リンク・世代位置、名前・国・IDの対応を検証してから統合する。
6. 実在しない実績・未測定値は観測値のまま作らず、必要なら学習期間だけで決めた推定とフラグを別契約で評価する。

今回追加した `repair_linked_history.py` は研究用の全結果照合・別DB修復経路である。
通常・フロントエンドの取得処理に全過去結果の自動取り込みを反映済みとは言わない。
既存の修復モード・結果完了表示も、全履歴・全特徴量欠損0の合格表示ではない。
モデル・購入ポリシー・本番DB・稼働中取得器の凍結コードは変更していない。

## 8. 必要な公開データだけを取得する見直し

通常取得へ `historical-jra-required-public-v1` を追加した。
レース本体に載る値は本体から取り、補助ページは、対象日前の公開成績と親識別に限定する。
平均・勝率・補間値は取得項目ではなく、観測後に学習期間と分離して計算する。
過去30日超の中央レースは、プロフィール → 表がない場合だけAjax → 出典確認済み血統の再利用とする。
現在の通算成績・通算賞金・所有者・生産地を過去学習用に追加保存せず、毛色の補助ページも要求しない。
公開通算件数は網羅性の監査メタデータだけに残す。既存値の一括削除・本番モデルの切替はしない。

適用対象は馬IDの数字形式だけで判断せず、ジョブのレースID・日付・中央区分から確認する。
中央の英数字馬ID・親IDと国名表記を保持する。
既存の親別名・IDが競合する場合は補完しない。直近・当日・将来・直接予測・地方の従来入力は維持する。
6時間以上古い現在プロフィールを新鮮なAjaxと混ぜず、必要な応答だけ更新する。
APIの取得方式・範囲の反映を確認できない画面は、新規実行を許可しない。
既存ジョブの監視・停止・所有者確認・承認lock・書き込みguardは変更していない。

実データの検証正本は `required-public-inputs-20261031-v3`。
馬 `2012102111`、対象日2016-01-10で、既存のプロフィール・Ajax原文と血統原文を使った。
公開表41行から対象日前14行を保持し、当日・未来27行を排除した。
この14行の対象区分は原文付きリンク台帳で保持し、中央の学習実績14走と読み替えない。
親3件の名前・IDを子馬と世代位置から照合し、不要なプロフィール値の追加保存は0項目だった。
初回の血統確認に追加通信1回を使用し、現コードのv3検証では同じ応答を再利用して追加通信0だった。
旧v1・v2は当時のコードでの記録であり、現コードの合格根拠にはv3を使う。

**この見直しは必要な観測への限定であり、全履歴DB取り込み・全欠損0・本番有効化の完了ではない。**
公開リンクの保存は結果の保存ではないため、`prior_results_imported=false` は維持する。
稼働中の全件血統取得と履歴91走の合流・全期間再計測は、前節の独立検証付き処理で継続する。
